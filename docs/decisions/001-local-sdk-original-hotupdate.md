# 决策记录 001：SDK 局域网化，热更新保留原站

> **分类**：架构决策记录 (ADR)  
> **状态**：已采纳 (Adopted)  
> **免责声明**：本文档记录的内容仅供逆向工程、协议分析与学术研究交流，严禁用于任何商业用途。

## 状态

已采用，适用于当前第一阶段验证。

## 决策

先将 SDK 登录和用户会话能力兼容到局域网 Python 服务端，再评估 APK SDK 域名重定向。YooAsset/HotUpdate 继续使用原始服务器。

## 原因

- SDK AES 协议和登录接口已经从 smali 中恢复。
- 本地服务端已经能够完成登录、Token、资料和系统信息的最小链路。
- 热更新域名 `pxcdn.jhdwxp.com` 目前只有 Host 级别抓包证据，完整路径、Manifest 和版本规则尚未确认。
- SDK API 与热更新资源下载是不同协议和不同故障边界，应该分开验证。

## 当前不做的事情

- 不修改 `桃.apk`。
- 不替换 `SdkDomainManager` 的内置域名。
- 不清除或修改 APK 的 `sdk_domains` 缓存。
- 不将 `pxcdn.jhdwxp.com` 指向局域网。
- 不实现充值、邮件、VIP、交易和完整账务接口。

## 后续接入条件

只有在以下条件满足后，才进行 SDK 域名重定向：

1. Python 服务端协议测试持续通过。
2. APK 等价加密请求能够在局域网服务端完成登录。
3. 已确认 SDK 的备用域名和 `sdk_domains` 缓存行为。
4. 确认热更新地址不需要同步修改。
5. 准备可回滚的 APK 修改和验证步骤。

## 风险

- 热更新后的 `HotUpdate.dll` 可能调用当前未实现的 SDK API。
- 服务端返回的最小模型可能不足以覆盖所有 UI 或游戏业务。
- 原始服务端可能在登录后通过其他接口验证 Token、游戏资格或版本。
- 原始热更新 CDN 可能使用动态路径、签名、平台参数或版本校验。

## 回滚

当前阶段没有 APK 修改，因此回滚只需要停止本地服务并恢复客户端原始 SDK 域名配置。任何后续 APK 修改都必须单独记录补丁文件、目标类和回滚方法。
